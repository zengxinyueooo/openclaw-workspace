**背景**：nail 采集链路自 03-30 起长期失效（CDP timeout、callFunctionOn 报错）。

**根因链路**：
1. Chrome 启动带 `--test-type` → CDP Runtime/Page 域 HTTP 500
2. 旧 browser.py 用 Playwright，沙箱里死锁
3. 新 browser.py（websockets CDP）复用旧 tab → tab 有残留 WS 连接 → Runtime.enable timeout

- env 文件的值有双引号，load_env 里加 strip('"') 去引号
- Venus 响应 `data` 字段是字符串 URL，不是 `{"url": ...}`，修了 `upload_to_venus`
- Supabase anon key 在 env 里（不是 SERVICE_KEY），修了 `insert_supabase`

## nail_collector.py 图片质量修复（12:00~14:00）

**问题**：入库的 nail 图全是无关图（樱花公园合照、高铁爆米花、机票截图等）。

**排查过程**：
- 以为是 `cover mask ld` parent class 过滤不精准 → 其实这个 class 搜索卡片也用，不是详情页专属
- 以为是 goto 详情页后 DOM 里混入其他图 → 实际更严重
- **根本原因**：小红书是 SPA，`page.goto("/explore/xxx")` 根本不会跳转到详情页
  - `Page.navigate` 触发后，服务器返回的就是 `/explore` 首页 HTML
  - 浏览器 URL 始终停在 `https://www.xiaohongshu.com/explore`
  - 笔记详情是前端 JS router 弹出的浮层，CDP `loadEventFired` 在首页加载完就触发了，浮层异步渲染后不再触发任何导航事件
  - 所以 goto 返回时，DOM 里全是搜索结果卡片的图，28 张 `.cover img` 全是其他笔记的封面

**尝试的无效方案**：
- `/discovery/item/xxx` URL → 同样重定向回 `/explore`
- `links[0].click()` → headless 模式 JS click 不能触发 SPA 路由弹窗
- 等 `fixed/absolute` 的 modal 元素 → 根本没弹出

**最终解法**：完全放弃进详情页，直接用搜索结果卡片封面图
- 搜索结果页 `.note-item .cover img` 的 src 就是 `notes_pre_post` 内容图（不是缩略图）
- 在搜索阶段顺手把 `cover_src` 带出来，主循环用 `_download_cover_image()` 直接下载
- 不需要任何 goto 额外跳转，速度大幅提升
- 3/3 验证：全部是真实美甲图 ✅

**教训**：
- 小红书 SPA 路由无法通过 CDP `Page.navigate` 跳转到子页面，这是架构级限制
- 搜索结果封面图本身就是高质量内容图，采集封面 = 采集笔记代表图，不需要进详情页
- 未来如果需要多图（一篇笔记取多张），需要研究如何触发 SPA 路由弹窗（CDP Input.dispatchMouseEvent 点击物理坐标）

## 下午：CDN 缓存问题排查与绕过

**现象**：requirement.html 和 requirement.js 部署后 CDN 一直不更新（last-modified 卡在 02:33），导致导航栏「需求详情」标签无法显示。

**根因**：webstatic CDN 对部分文件有强缓存（文件大小从大变小时尤其明显），deploy 成功但 CDN 边缘节点不主动拉取新版本。没有 CDN purge API 权限（401）。

**最终解法**：在 auth.js（CDN 上最新）里加 `patchNav()` 函数，所有页面加载时自动检测导航栏缺失的「需求详情」链接并注入。不依赖 requirement.html 更新。

**教训**：
- webstatic deploy token 会限流/失效，不能无限重试
- CDN 文件缓存是按文件粒度的，大文件 TTL 更长
- 绕过 CDN 缓存的最佳方案：通过已正常更新的 JS 文件（如 auth.js）动态注入内容

## 晚上：available_materials view 根因排查（20:48~20:53）

**背景**：皮皮询问「审核通过后素材会不会失误进不了 available_materials」

**结论**：
- `available_materials` 是 **VIEW**（不是独立的表），定义 = `SELECT ... FROM materials WHERE status='approved' AND category IS NOT NULL`
- 机制上不会失误：`status` 改成 `approved` 即自动出现，无 trigger、无同步
- **发现 8 条 approved 素材 view 里查不到**（batch=manual_20260305，`status=approved`、`category=face`、`used_by=NULL`，完全符合 view 条件）
- 推断：线上实际运行的 view 定义和本地 SQL 文件不一致，可能历史 migration 被覆盖
- **待确认**：皮皮在 Supabase 控制台执行 `SELECT view_definition FROM information_schema.views WHERE table_name = 'available_materials';` 查线上实际定义
