## 采集链路故障排查（重要）

### 问题
松鼠颜值素材采集连续失败，所有关键词返回：
> `Account abnormal. Switch account and retry.`

### 根因（确认）
`face_collector.py` 的方案：先跳 `www.xiaohongshu.com/search_result` 触发登录态，再在页面内用 `fetch` 调 `edith.xiaohongshu.com/api/sns/web/v1/search/notes`。

**该 API 需要请求头签名（X-Sign 等），裸 fetch 无签名 → 被风控拒绝。**
不是账号问题，是接口鉴权变了。新账号重新登录也无效。

### 解决方向（待实施）
- **方案 A**：在 fetch 时注入签名头（复用页面已有签名函数）
- **方案 B（更推荐）**：改为 DOM 解析方案，直接抓搜索结果页卡片 DOM，不走 edith API，彻底绕开签名问题

皮皮确认先试方案 A（注入签名头）。

### 方案 A 实施结果（11:16 验证通过）

松鼠改造 `face_collector.py`，核心方案：

1. 跳到小红书搜索页（带登录态），等页面自动发出 `search/notes` 请求
2. **CDP `Network.requestWillBeSent` 拦截**真实请求，抓取 `X-s`、`X-S-Common`、`x-rap-param` 签名头
3. 单独用 `Network.getAllCookies` 补全 Cookie（拦截事件里不含 Cookie）
4. 直接复用拦截到的 `postData`（含真实 `search_id`），用真实签名 + Cookie 重新 POST 一次

**踩坑**：自己构造 body 时 `search_id` 为空 → 返回 0 条 → 解决：复用原始 `postData` 不重建 body

**测试结果**（关键词：夜间氛围感拍照，目标10张）：
- API 返回 22 条 → 下载 19 张 → YOLO 过滤 → **8张入库**（批次 `face_20260409_111519`）
- 采集链路恢复正常，下次 cron 可跑全量7个关键词

## 素材图片清晰度修复（11:30~11:44）

### 问题
入库图片模糊，怀疑取的是缩略图。

### 排查过程
1. 最初代码：`cover_info.get("url_pre") or cover_info.get("url", "")` → 取缩略图
2. 改为优先 `url` → 但经 DEBUG 确认 cover 对象根本没有 `url` 字段
3. cover 实际字段：`height`、`width`、`url_default`、`url_pre`
4. **最终修复**：改为 `cover_info.get("url_default") or cover_info.get("url_pre", "")`

### 结论（铁律）
- 小红书 search/notes API 的 `cover` 对象字段：`url_default`（高清）、`url_pre`（缩略图）
- 取图优先级：`url_default` > `url_pre`，没有 `url` 字段
- face_collector.py 已更新，11:44 起生效
